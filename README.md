# 叙镜 · NarraLens

> 让文案成为视频。

**文案驱动的视频制作工作台 · v2.9.1**

[English](README-en.md) · 使用说明 · [MIT许可证](LICENSE)

## 项目简介

叙镜（NarraLens）是一款以完整文案为核心的视频制作工作台。用户提供文案和本地视频素材，软件利用素材库分析与检索结果，为文案组织镜头，生成连续配音、字幕和成片；按需要加入背景音乐和解释动画。

适合影视深度解析、长篇解说和围绕已有文案组织画面的制作流程。文案可以与单集剧情保持较弱对应关系，多个素材库可以联合检索。最终画面与原素材、分析质量和配置的模型能力有关，生成后可查看匹配详情。

## 主要功能

- **内容拉片与复用**：联合字幕和关键帧记录人物、时期、事件与证据，以内容段组织真实镜头。后续文案查询事件，再匹配已保存的镜头观察；疑难部分可局部补分析。
- **完整文案输入**：支持粘贴正文及TXT／Markdown，原稿和项目输入副本可追溯。
- **按句意组织画面**：从一个或多个视频素材库检索实际镜头，按当前原文范围检查内容关系，在连续配音下安排多个镜头；素材不足时报告缺口。
- **长段配音**：按原文段落建立配音块，支持手动合并／拆分；当前默认块间停顿3秒。
- **本地字幕对齐**：使用独立Qwen3 ForcedAligner环境生成字词时间；关闭时保留字幕并按文字估算时间。
- **单行字幕排版**：字号可自定义，按文字实际宽度和可用时间调整字幕切换。
- **自动BGM**：分析音频库中的整首音乐，再按文案主题和情绪选曲，支持整篇单曲与分段配乐。
- **解释动画**：支持自动、手动及混合插入，原文范围确定时机，可预览对应配音时间。
- **项目管理**：新建、查看、复用、删除，与制作设置和推进分开。
- **分阶段继续**：保留通用继续与1–5阶段入口，使用已有配音和有效结果恢复制作。
- **模型集中配置**：按用途选择接口、实际模型和参数，文案及视觉各有后备配置。

## 运行与模型准备

### 当前Windows工作区

本地修改版当前使用以下布局，实际路径以部署位置为准：

```text
工作区/
├─ start.bat
├─ .conda/
│  ├─ narratoai/              主应用环境
│  └─ narratoai-align/        本地对齐环境
├─ models/
│  └─ Qwen3-ForcedAligner-0.6B-hf/
└─ NarraLens/                当前实际代码目录
   ├─ webui.py
   ├─ config.toml
   └─ storage/
```

在现有环境和依赖已经安装的工作区，运行上一级的start.bat，然后在浏览器打开 `http://127.0.0.1:8501`。启动窗口保持打开，Ctrl+C用于停止应用。

当前代码目录为NarraLens，启动脚本指向该目录。视频原文件继续使用登记路径。2.8使用新的内容拉片结构；旧窗口库需创建独立拉片副本再分析，具体步骤见下文。

其他部署位置或新电脑需要先准备应用依赖、FFmpeg及所需模型／服务，不能仅复制启动脚本就认为环境已经安装。现有环境与本地对齐的部署记录见对齐环境与模型部署。该记录针对当前机器，硬件与路径需按实际环境配置。

### 模型使用

应用在本地管理素材、项目与生成结果。文本／视觉／音频分析、配音是否访问外部服务，由当前选择的模型接口决定；在素材分析时，所选服务会接收对应文案、字幕、图片或整首音频。

进入“模型配置”查看配置名称、实际模型、用途、字段状态和参数。接口字段已填写只说明配置完整性，真实能力与连接需通过显式检查或对应流程确认。

文案项目可选择已登记的MiMo、Edge、豆包、腾讯、Qwen3 TTS、Azure、SoulVoice，以及IndexTTS、OmniVoice、VoxCPM等已有接口适配器。配置与音色参数在“制作工作台 → TTS 配音设置”选择；待完善配置也会显示，需先在“模型配置”补齐字段。已有本地TTS通过其HTTP服务调用，本项目不自动安装或启动模型。各服务的实际连通及音质仍需自行验证。

逻辑配音块保留最多12000汉字和块间3秒停顿。其他服务按请求限制继续拆分，内部顺序拼接不额外加3秒：Qwen按600字符、腾讯混合文本保守按150字符、豆包现有v1接口按1024个UTF-8字节，其他新适配默认500字符。中央高级服务参数`request_max_chars`／`request_max_bytes`可调整应用分块大小，已知接口上限不能调大。长段模式仍使用实际音轨进行本地字幕对齐。

更换已有项目的配音：先选好新服务和音色，展开“复用副本”，取消“沿用历史任务配音设置”，点击“创建复用副本并生成”。普通继续使用项目保存的配音配置，原项目与已有音频保留。新配音需要重新对齐并计算画面、动画和配乐时序。

Azure／腾讯SDK按服务区域选接口，接口地址留空；Qwen自定义地址使用DashScope原生API根地址。豆包当前复用旧v1适配器，未新增v3／2.0音色协议。高级参数是否生效以相应适配器为准。文本和视觉后备继续使用独立接口及凭据，按现有规则执行。

### 字幕时间戳模型

“文案生成视频”的长段配音默认使用 [Qwen/Qwen3-ForcedAligner-0.6B-hf](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B-hf) 在本地进行强制对齐。输入已合成的配音和对应原文，推理字词的发声起止时间，再映射为字幕时间戳；中文以字为主要对齐单位。所选文案／字幕模型负责规划语义分段。

- 模型在对齐阶段有未完成块时才由独立进程加载；成功时间戳缓存可以复用，进程退出后释放GPU资源。
- 超过5分钟的配音块会自动定位边界并分窗对齐，继续复用已有配音。
- 需要单独准备PyTorch／Transformers对齐环境及本地权重。当前GPU工作进程使用BF16和cuda设备接口；AMD显卡需可用的ROCm环境。
- 本地对齐默认开启；关闭后仍保留字幕，按音频时长和文字权重估算时间，可能与实际发声有偏差。

解释动画使用已配置的Node、Remotion和浏览器渲染环境；相应准备与回退见解释动画施工说明。

## 完整文案制作流程

### 1. 配置模型

在“模型配置”维护所需接口、凭据和参数；各工作区选择对应用途的配置。已导入定义可直接编辑，无需每次重新导入。

### 2. 建立视频素材库

选择视频和字幕目录，扫描并检查匹配关系，再登记、分析素材。支持ASS／SSA及SRT；多个字幕候选需选择目标字幕，ASS可选择中文样式或所在行并检查预览。

视频原文件保留路径引用，库内保存字幕副本、抽帧、观察证据及事件目录。分析按同一视频分批，可配置并发和批量；每批只是请求边界，内容段可以跨批延续。长镜头采样间距控制局部准备，不代表按固定秒数划分事件。

“作品与资料”可导入MD、人物别名／时期／参考镜头、集号映射，或获取Bangumi公开条目。资料保留来源，只辅助理解，不作为某镜头出现具体事件的证据。无外部资料仍可分析。

“内容浏览与质量修正”支持查看事件、镜头、字幕和帧引用，预览原片，补分析当前镜头，更正时期或画面属性。相似采样仅作提示；人工确认重复后可指定同一重复组，全片编排会去重。

### 3. 按需要建立音频素材库

登记本地音乐，通过支持音频输入的配置分析整首音频。建立好的情绪、风格、节奏和用途资料供自动BGM选择，也可手动选曲。

### 4. 登记文案项目

进入“项目管理”，粘贴完整文案或上传TXT／Markdown，选择一个或多个视频素材库并创建项目。

### 5. 在制作工作台推进

选择项目后设置：

- TTS服务、音色、参考音频、配音块和衔接停顿。
- 文案／字幕／视觉模型及后备。
- 字幕字号、画幅及输出选项。
- BGM来源、配乐方式和音乐音量。
- 解释动画模式、手动节点和内容。

保存设置并开始制作。文案与素材分析、配音、字幕对齐、画面检索及动画、配乐、视频合成按流程执行。

### 6. 查看与调整

查看成片、匹配详情、字幕／动画方案及项目内诊断记录。已经开始的项目可通过复用副本应用需要重做的设置；来源项目与已有产物保留。

画面单元独立于TTS分段，使用已有配音时间绑定具体句意。匹配详情分页显示原文范围、来源、直接／辅助关系及依据；未完成时也可查看缺口。具体剧情要求直接对应，辅助画面只用于允许的状态／抽象范围，未通过评选的镜头不再自动作为过渡填入。素材不足时补充素材或为合适范围设置解释动画后继续，已有配音、字幕和旧成片保留。

详细操作见视频与音频素材库、文案驱动生成。

## 升级到2.8与继续制作

1. 已是内容拉片结构（schema 2）的库直接打开使用。只有旧窗口库才显示 **创建 2.8 拉片副本**：复制登记和库内字幕、引用同一原视频，旧库保留。
2. 在新库确认作品／版本与字幕。可先选择一两集建立拉片，查看内容与证据后再继续其余素材。
3. 在项目管理新建项目，或在制作工作台创建复用副本并选择新库。匹配的配音、字幕及对齐缓存可继续复用；画面需求与镜头匹配使用2.8协议重新建立。
4. 通过 **3. 寻找画面** 推进。后续继续复用已付费观察与有效匹配，沿保存的事件检索游标追加；每个缺口区分资料未完成、模型未确认、时长／占用不足与未检索到相关事件。

具体剧情仍需有范围内的可见证据；评论、理论和修辞使用有依据的关联画面，不要求单个镜头证明作者立场。必要的事件先后关系保留，观点或属性排列不自动要求独立镜头按编号出现。原片来源去重、片尾排除、镜头最短时长与连续配音时轴仍会校验。

旧库、原片、旧项目配音／字幕／动画及成片不会因升级自动改写。旧窗口语义结果不会伪装为新拉片结果；2.8没有在后台自动重建全库。原任务需要切换新库时优先建立复用副本。

项目仍可通用继续或使用编号1–5的阶段入口。删除位置：**项目管理 → 管理项目 → 检查文件与删除范围 → 确认 → 永久删除当前项目**。

## 外部 Agent 独立拉片（2.9）

视频素材库的“拉片任务”现在可选择 **自动拉片／外部 Agent**。使用外部Agent时：

1. 选择需要处理的素材，展开“外部 Agent 任务”，点击 **创建 Agent 拉片任务**。
2. 本地准备镜头、字幕快照和稀疏预览。点击任务指令代码框的复制按钮，将指令交给支持本机文件、看图和命令调用的Agent。
3. Agent读取任务目录中的 `TASK.md`，使用配套CLI按集查看字幕和图片、请求补帧／裁剪、保存观察及内容分组。
4. 在NarraLens刷新任务进度，点击 **检查结果**，核对可导入项、已有项、输入冲突及待补项，再点击 **导入合格结果**。
5. 导入后继续使用原来的内容浏览和文案检索。部分观察可以先导入，目录和剩余范围随后补齐。

任务保存在 `storage/agent_analysis_tasks/任务ID/`，只读引用原视频；任务拥有字幕快照、证据图片、提案和回执。导入后的图片归素材库所有，移除任务目录会保留已导入证据和原媒体。

CLI入口为 `python -m app.services.library.agent_tasks`，提供 `describe`、`overview`、`ranges`、`view`、`capture`、`references`、`submit`、`stop`、`resume`。生成的TASK.md含当前Python环境、工作目录和具体命令。正式入库由WebUI处理，CLI提交只保存草稿。

本地准备与检查不调用模型。Agent使用它自己的模型与账号；使用云端模型时仍需联网。当前版本采用手动交接任务，不包含MCP服务或特定Agent的一键启动器。停止标记只约束后续本地工具调用，外部模型请求应在Agent应用中停止。

## 2.9.1版本说明

本版统一源帧定位：按显示顺序记录真实帧号与整数 PTS／time_base，物理镜头和分析范围采用起点包含、终点不包含的帧区间。镜头编号和来源去重不再使用“秒数 × 平均帧率”。

- 一次顺序扫描建立帧表与镜头切点，只保存元信息和按需证据图；完成后复用索引，中断视频需要重新扫描。
- 普通拉片和外部 Agent 共用取帧入口。Agent 的 `capture` 支持 `--time` 或 `--frame`，解码后核对实际源帧；同帧裁剪引用同一父帧。
- 长镜头目标时长仍按秒设置，字幕附近的分段落到实际帧边界。范围详情展示源帧号与实际时间。
- 检索补观察保留完整范围和证据基线，剪辑记录携带源视频流及时间原点；配音和成片的输出时钟继续独立计算。

**旧索引、旧拉片结果及旧 Agent 任务不兼容。** 保留视频／字幕登记及作品资料，重新建立拉片和 Agent 任务；旧来源缓存不能用于新剪辑。程序不会在打开页面时自动删除资料。原视频、字幕原件与音频素材库不受本次协议变更影响。

本版完成源码静态检查；未运行自动测试、实际取帧、模型建库、Agent 任务、WebUI 交互或完整成片验收。首次建立帧表仍会使用 CPU 解码全片；索引只提高定位一致性，不保证自动切镜与画面理解完全正确。

## 2.9.0版本说明

新增独立Agent任务服务与CLI，复用现有媒体处理、观察／分组校验和库事务。任务目录使用跨进程锁，输入与取证回执绑定来源身份；按实际解码时间记录补帧。局部导入不清整集，导出后的新修订会显示冲突，相同成果重复导入跳过。

分析基线与实际证据修订分开：普通“继续”可复用已导入观察；增加取证图片不会仅因帧数变化而重新付费分析。自动拉片、schema 2、现有TTS／对齐／BGM／解释动画和合成流程继续使用。

本版完成代码静态检查；未运行自动测试、真实取帧、外部Agent、实际WebUI交互、模型建库或完整成片验收。图片理解质量及耗时收益仍待实际对照。
