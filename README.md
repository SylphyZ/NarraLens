# 叙镜 · NarraLens

> 让文案成为视频。

**文案驱动的视频制作工作台 · v2.7.10**

[English](README-en.md) · [MIT许可证](LICENSE)

## 项目简介

叙镜（NarraLens）是一款以完整文案为核心的视频制作工作台。用户提供文案和本地视频素材，软件利用素材库分析与检索结果，为文案组织镜头，生成连续配音、字幕和成片；按需要加入背景音乐和解释动画。

适合影视深度解析、长篇解说和围绕已有文案组织画面的制作流程。文案可以与单集剧情保持较弱对应关系，多个素材库可以联合检索。最终画面与原素材、分析质量和配置的模型能力有关，生成后可查看匹配详情。

## 与NarratoAI的关系

## 主要功能

- **素材分析与复用**：视频素材和音频素材独立登记，保存分析结果，后续项目继续使用已有结果。
- **完整文案输入**：支持粘贴正文及TXT／Markdown，原稿和项目输入副本可追溯。
- **按句意组织画面**：从一个或多个视频素材库检索实际镜头，按当前原文范围检查内容关系，在连续配音下安排多个镜头；素材不足时报告缺口。
- **长段配音**：按原文段落建立配音块，支持手动合并／拆分；当前默认块间停顿3秒。
- **本地字幕对齐**：使用独立Qwen3 ForcedAligner环境生成字词时间；关闭时保留字幕并按文字估算时间。
- **单行字幕排版**：字号可自定义，按文字实际宽度和可用时间调整字幕切换。
- **自动BGM**：分析音频库中的整首音乐，再按文案主题和情绪选曲，支持整篇单曲与分段配乐。
- **解释动画**：支持自动、手动及混合插入，原文范围确定时机，可预览对应配音时间。
- **项目管理**：新建、查看、复用、删除，与制作设置和推进分开。
- **分阶段继续**：保留通用继续与1–5阶段入口，使用已有配音和有效结果恢复制作。
- **模型集中配置**：按用途选择接口、实际模型和参数，文案及视觉各有后备配置。

## 运行与模型准备

### 从源码运行

需要Python 3.12、FFmpeg及本项目的Python依赖。在准备好的环境中，从源码目录运行：

```powershell
python -m pip install -r requirements.txt
python -m streamlit run webui.py --server.address=127.0.0.1 --server.port=8501
```

浏览器打开 `http://127.0.0.1:8501`。源码不包含本机Conda环境、模型权重、原素材或生成结果。本地字幕对齐和解释动画需要另行准备对应环境、模型及Node／Remotion依赖。

本仓库从NarraLens v2.5.0开始记录独立提交历史，原项目来源和许可证保留。施工文档仅在维护者本地保存。

### 模型使用

应用在本地管理素材、项目与生成结果。文本／视觉／音频分析、配音是否访问外部服务，由当前选择的模型接口决定；在素材分析时，所选服务会接收对应文案、字幕、图片或整首音频。

进入“模型配置”查看配置名称、实际模型、用途、字段状态和参数。接口字段已填写只说明配置完整性，真实能力与连接需通过显式检查或对应流程确认。

文案项目可选择已登记的MiMo、Edge、豆包、腾讯、Qwen3 TTS、Azure、SoulVoice，以及IndexTTS、OmniVoice、VoxCPM等已有接口适配器。配置与音色参数在“制作工作台 → TTS 配音设置”选择；待完善配置也会显示，需先在“模型配置”补齐字段。已有本地TTS通过其HTTP服务调用，本项目不自动安装或启动模型。各服务的实际连通及音质仍需自行验证。

逻辑配音块保留最多12000汉字和块间3秒停顿。其他服务按请求限制继续拆分，内部顺序拼接不额外加3秒：Qwen按600字符、腾讯混合文本保守按150字符、豆包现有v1接口按1024个UTF-8字节，其他新适配默认500字符。中央高级服务参数`request_max_chars`／`request_max_bytes`可调整应用分块大小，已知接口上限不能调大。长段模式仍使用实际音轨进行本地字幕对齐。

更换已有项目的配音：先选好新服务和音色，展开“复用副本”，取消“沿用历史任务配音设置”，点击“创建复用副本并生成”。普通继续使用项目保存的配音配置，原项目与已有音频保留。新配音需要重新对齐并计算画面、动画和配乐时序。

Azure／腾讯SDK按服务区域选接口，接口地址留空；Qwen自定义地址使用DashScope原生API根地址。豆包当前复用旧v1适配器，未新增v3／2.0音色协议。高级参数是否生效以相应适配器为准。文本和视觉后备继续使用独立接口及凭据，按现有规则执行。

### 字幕时间戳模型

“文案生成视频”的长段配音默认使用 [Qwen/Qwen3-ForcedAligner-0.6B-hf](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B-hf) 在本地进行强制对齐。输入已合成的配音和对应原文，推理字词的发声起止时间，再映射为字幕时间戳；中文以字为主要对齐单位。所选文案／字幕模型负责规划语义分段。

- 模型在对齐阶段有未完成块时才由独立进程加载；成功时间戳缓存可以复用，进程退出后释放GPU资源。
- 超过5分钟的配音块会自动定位边界并分窗对齐，继续复用已有配音。
- 需要单独准备PyTorch／Transformers对齐环境及本地权重。当前GPU工作进程使用BF16和cuda设备接口；AMD显卡需可用的ROCm环境。
- 本地对齐默认开启；关闭后仍保留字幕，按音频时长和文字权重估算时间，可能与实际发声有偏差。

解释动画使用单独准备的Node、Remotion依赖和浏览器渲染环境。

## 完整文案制作流程

### 1. 配置模型

在“模型配置”维护所需接口、凭据和参数；各工作区选择对应用途的配置。已导入定义可直接编辑，无需每次重新导入。

### 2. 建立视频素材库

选择视频和字幕目录，扫描并检查匹配关系，再登记、分析素材。支持ASS／SSA及SRT；多个字幕候选需选择目标字幕，ASS可选择中文样式或所在行并检查预览。

视频素材通常保留原路径引用，库内保存字幕副本、抽帧和分析结果。成功分析可复用，停止后可以继续。

### 3. 按需要建立音频素材库

登记本地音乐，通过支持音频输入的配置分析整首音频。建立好的情绪、风格、节奏和用途资料供自动BGM选择，也可手动选曲。

### 4. 登记文案项目

进入“项目管理”，粘贴完整文案或上传TXT／Markdown，选择一个或多个视频素材库并创建项目。

### 5. 在制作工作台推进

选择项目后设置：

- TTS服务、音色、参考音频、配音块和衔接停顿。
- 文案／字幕／视觉模型及后备。
- 字幕字号、画幅及输出选项。
- BGM来源、配乐方式和音乐音量。
- 解释动画模式、手动节点和内容。

保存设置并开始制作。文案与素材分析、配音、字幕对齐、画面检索及动画、配乐、视频合成按流程执行。

### 6. 查看与调整

查看成片、匹配详情、字幕／动画方案及项目内诊断记录。已经开始的项目可通过复用副本应用需要重做的设置；来源项目与已有产物保留。

画面单元独立于TTS分段，使用已有配音时间绑定具体句意。匹配详情分页显示原文范围、来源、直接／辅助关系及依据；未完成时也可查看缺口。具体剧情要求直接对应，辅助画面只用于允许的状态／抽象范围，未通过评选的镜头不再自动作为过渡填入。素材不足时补充素材或为合适范围设置解释动画后继续，已有配音、字幕和旧成片保留。

## 继续、复用与删除

项目可使用通用继续或编号1–5的阶段入口，从指定阶段推进。匹配的已有成果可复用，具体前置条件由各阶段验证。

2.7升级后，旧时间轴请从 **3. 寻找画面** 重新选片，可复用配音、字幕与对齐；旧时间线不能直接从第4／5阶段绕过句意检查。重选会在项目的 `history/visual-*` 中留存原成片及时间轴。关闭“确认候选画面”时，内容关系仍按已有描述与实际范围字幕判断，并标为未进行本次视觉复核；片尾／演职员画面检查仍独立使用视觉模型。

2.7.1兼容已有对齐中的零时长字词，使用正时长发声锚点定位画面，保留完整原文。因该问题停在画面规划的项目可从第3阶段继续，复用原配音和字幕；全部没有正时长或时间记录确实无效时仍会明确报错。

2.7.2将候选字幕引用改为范围限定的编号，程序按编号恢复原句；可定位的单镜头字段错误只拒绝该候选，保留同批有效结果，格式未确认与内容不足分别记录。应用新协议请从 **3. 寻找画面** 继续，可复用原配音、字幕、对齐和独立画面可用性缓存；原成片与时间线保留，不需要重新分析素材库。

2.7.3从第3阶段采用节省Token的选片调度：恢复已有合格候选，本地整理与可跳过的文字预选后先拟定全片方案，只对拟用镜头做必要确认。单元连续无新增合格时长时暂停扩大，继续可复用缓存并追加检索；工作台显示本次与累计已报告Token。配音、字幕和对齐可复用，原成片保持，临时方案不能直接用于合成。

2.7.4在原句意分组之后，核对动画原文绑定、实际占用和发声间隙，归并半帧取整引起的共享边界残段。遇到此前三处不足1秒区间的项目，可从 **3. 寻找画面** 继续；配音、字幕和动画无需重做。纯边界修正且原计划、素材库和模型设置均匹配时，复用旧候选池和检索游标；真正的短区间或绑定冲突仍暂停并说明原因。

2.7.5修复新候选无法从待审转为合格的状态冲突；保留已确认条目，只对必要的格式错误追加一次小批纠错。旧缺口中被当作具体事实的抽象评论可定点复核，真实剧情约束保留。未改需求的单元继续复用检索进度，变化单元按新要求核对已有范围。升级后从 **3. 寻找画面** 继续；必要纠错和需求复核会调用所选模型并计入Token，剩余真实缺口仍会报告。

2.7.6对文字预选逐项校验编号，保留合法建议，空选时只保留少量待审核备选；预选错误不再成为整组画面未确认。需求修订后，仅在原文、范围、模型缓存身份及正式门槛均能证明兼容时复用旧批准。无改善轮次按已完成的有效评估结算，另行报告协议问题、分配冲突和实际审片未确认。升级后从 **3. 寻找画面** 继续；新增审核仍计入Token，真实素材缺口继续保留。

2.7.7将临时来源冲突和实际审核未确认保存到候选进度，优先换取其他范围；一小批本地窗口没有产出时继续查找。再次继续会沿候选队列和检索游标推进，复用已付费结果。多余回复编号单独拒绝，有效同行保留；符合严格条件的明确否定可本地校验后复用。有效无改善仍按用户设置停止，事实、待审、来源去重和片尾门槛保留。升级后从 **3. 寻找画面** 继续，新增实际审核仍计入Token。

2.7.8将ASS的语言筛选与正文／歌词／注释角色分开，保留中性样式中的中文正文。视频素材库提供字幕校验、本地正文与窗口索引恢复及单素材回退；旧字幕文件与视觉分析保留，待补字幕语义单独标记。寻找画面前拦截已确认的正文丢失；实际审核按单个文案单元组织多个候选。具体事件拆成有原文绑定的事实，由最终实际采用的多个镜头共同覆盖；不重复、不入片尾及最低镜头时长继续检查。升级后先在视频素材库校验／恢复资料，再从 **3. 寻找画面** 继续；模型审核和完整成片效果仍需实际验收。

2.7.9将缺口画面需求修订统一为原文词片编号：模型选择范围，程序恢复引文、偏移与事实编号；不再要求模型反复抄原句或维护旧事实的多套编号。有效同行立即保存，未通过项附具体字段错误做一次局部纠正；仍未完成时保存为可继续的暂停。解析结果、请求引用与业务校验结果保存在同一批审计中。兼容的旧成功需求可复用，升级后从 **3. 寻找画面** 继续；新增整理与纠错仍计入Token。这次没有重跑模型或生成任务，实际需求质量和完整视频仍需验收。

2.7.10为寻找画面加入不同文案单元的有限并发，默认4，可在输出高级设置调整，设1沿用同一流程串行审核。每次请求仍独立核对一个单元及少量拟用候选；冻结原文与来源身份，任务线程统一接收回包、保存审计和计量，再按波次编排。按剩余时长限制提交数量，临时预留来源，保留事实覆盖、片尾、去重及最低镜头时长检查。新回包记录可在缓存提交中断后定向恢复，旧兼容缓存继续复用。重启后从 **3. 寻找画面** 继续。代码与静态核对分开记录；尚未执行并发模型实跑、速度／Token对照或完整成片验收，不承诺固定提速比例。

改变已经生成的配音／字幕／动画或配乐时，按制作工作台提供的副本入口操作。

删除项目的位置：**项目管理 → 选择项目 → 管理项目 → 检查文件与删除范围 → 确认 → 永久删除当前项目**。删除清理当前项目及其产物，原素材与外部文案文件保留；运行中的关联资源需要先停止。

代码ZIP与项目数据承担不同恢复用途：代码备份通常排除storage、媒体、环境和权重；需要保存成片和项目成果时另外备份对应数据。
